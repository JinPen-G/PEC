## 1. 背景与目标

Preview 从 HTML 原型承载工具演进为独立的原生 React 原型管理平台。平台自身提供真实账号、会话、项目授权、管理后台和轻量实时协同；项目中的订单等业务只演示前端交互，使用合成模拟数据，没有真实业务服务端。

浏览器端是一套应用、一个登录入口和同一套外壳，按服务端确认的角色显示工作台。平台管理员采用 Rental OS SaaS 管理员的布局/使用方式管理账号、项目与授权，普通用户进入获授权项目；不建设另一个后台站点、后台登录页或隐藏的管理入口。

项目开发方式类似脚手架：各项目有独立页面注册、客户端、菜单、资源与模拟数据，复用统一的前端底座。平台产品与 Rental OS 属于同一系列，通过固定版本前端来源及受控同步快速跟进风格升级。

目标是形成可持续开发的产品基础，不承诺仅因使用 React 就自然消除卡顿；性能由可测量的加载、切换与协同表现验收。

## 3. 产品结构与概念

```text
独立 Preview 平台
├─ 统一登录与真实会话
└─ 同一应用外壳，按真实角色呈现
   ├─ 平台管理员：账号 / 项目 / 成员 / 客户端 / 菜单 / 系统配置
   └─ 项目用户：获授权项目列表与工作空间
      ├─ 项目 A
      │  ├─ 管理端：菜单与原生页面
      │  └─ 用户端：菜单与原生页面
      └─ 项目 B
         ├─ 企业端
         └─ 移动端演示入口
```

客户端是项目的展示分面，不是新的租户或经营空间。成员权限以项目为基本单位，首期不再引入独立客户端账号、客户端角色或细粒度业务按钮权限。

复用的是 SaaS 平台管理员的界面与按角色落地方式，不引入 Rental OS 的租户、订阅、经营空间和账号服务。Preview 仍保持独立工程、账号数据和部署；统一前端入口不取消真实平台 API。

同一个普通账号可以是项目 A 的查看者、项目 B 的编辑者。项目内原型的模拟按钮操作不等同于维护项目配置，查看者也可以体验原型已提供的前端交互。

## 5. 用户与权限

### 5.1 角色矩阵

| 动作                                 | 平台管理员     | 项目编辑者     | 查看者         |
| ------------------------------------ | -------------- | -------------- | -------------- |
| 管理平台账号、重置密码、设平台角色   | 允许           | 不允许         | 不允许         |
| 新建、归档项目                       | 允许           | 不允许         | 不允许         |
| 分配项目成员及编辑/查看角色          | 允许           | 不允许         | 不允许         |
| 查看项目列表与工作台                 | 全部有效项目   | 自己获授权项目 | 自己获授权项目 |
| 修改项目展示资料、客户端及菜单       | 允许           | 仅授权项目     | 不允许         |
| 体验订单示例与本地查询交互           | 允许           | 允许           | 允许           |
| 查看同项目在线人员、鼠标，主动跟随   | 当前项目内允许 | 当前项目内允许 | 当前项目内允许 |
| 分享管理后台页面、密码、真实账号操作 | 不提供协同     | 不提供协同     | 不提供协同     |

平台角色与项目成员角色分开存储。普通成员不能通过修改请求体、URL、浏览器存储或关联的客户端 ID 升权。管理员的全项目能力也必须由服务端真实身份判定。

### 5.2 账号生命周期

- 由管理员创建账号；首期不开放注册，不要求外部短信或邮件服务。
- 登录成功建立真实服务端会话；错误凭据不创建会话，禁用账号不能登录。
- 首次管理员通过受控初始化流程建立，不提供共用的生产默认密码。
- 用户可修改自己的密码；管理员重置账号后可要求下次改密。密码、重置凭据与会话令牌不进入协同、日志或项目配置。
- 禁用账号、重置密码、退出登录按会话策略撤销相应访问；不能仅清掉浏览器字段。
- 禁止禁用或降级最后一个有效平台管理员；服务端处理并发约束。
- 账号停用、撤销项目授权后，已有页面与实时连接都必须失去相关访问能力。

### 5.3 项目权限异常

未登录引导登录；未获授权不返回项目名称、成员、菜单、资源或协同人员。通过收藏链接直达也必须检查。已登录但无项目时显示无可访问项目和联系管理员的合理状态，不自动加入示例项目。

访问失效时清理对应查询缓存、选择、草稿和协作状态；旧请求晚到不能将前一个账号/项目数据重新显示出来。成员角色变更不得等到重新登录才生效。

## 6. 统一应用与按角色工作台

### 6.1 统一登录与角色落地

所有用户使用同一个登录页和会话流程，登录后读取服务端确认的身份、平台角色及有效项目：

- 平台管理员直接进入平台管理工作台，默认展示项目管理和已有管理导航，不填虚构的 SaaS 收入/租户仪表板。
- 普通用户进入获授权项目列表，选择项目后进入对应工作台；编辑者在该项目范围内显示允许的配置菜单。
- 管理员可以在同一应用内进入任意有效项目演示，再通过原有导航回到平台管理，无需换账号、第二次登录或切换站点。

不要求用户在登录页自行选择管理员/普通用户身份，也不通过 URL、浏览器存储、另一个登录接口或隐藏快捷键取得管理入口。退出后重新登录不得继承上一个账号的项目、菜单或草稿。

项目卡片只展示项目名称、描述、图标、本人角色及可用入口，不编造订单、收入或活跃数据。搜索与排序属于列表自身状态，不能扩大权限。

### 6.2 工作空间与客户端

- 顶部或侧栏的工作空间切换器负责切换项目，只列有权访问的项目。
- 进入项目后切换其客户端，客户端菜单与页面跟随切换。
- 有效客户端优先恢复该账号在该项目的最后选择；失效则回到首个可用客户端，不跳入其他项目。
- 切换项目需要结束原项目的跟随与在线状态，清理项目作用域状态，不自动把跟随者带到别的项目。
- 没有客户端或没有业务页时不报脚本错误，内容画布留空；可在选择器或框架上下文说明当前没有可用入口。
- 不在空画布填充欢迎页、统计卡片、模拟业务图表或旧 HTML。

### 6.3 工作台界面

沿用 Rental OS 同系列的侧栏、顶栏、面包屑、账号菜单、控件、主题与动效。接入 Preview 自己的品牌、菜单、账号和项目动作。保留现有语言/主题偏好，窄屏可使用导航抽屉，减少动态偏好生效。

同一外壳按角色生成菜单：管理员显示平台管理分组，普通用户显示项目导航，编辑者额外显示本项目配置。可使用应用内部逻辑路由区分页面，但不能部署为第二套后台或增加后台登录入口。

协作入口只放在项目内容工作台上下文中，展示在线成员与自己的跟随状态；平台管理页面不进入演示跟随。SaaS 管理员外观由固定来源适配，业务菜单、账号动作和权限使用 Preview 自己的实现。

项目工作台右上角原 Copilot 按钮的位置改为“本页文档”，使用 Copilot 式侧窗阅读当前页关联文档；原菜单中的“Agent 工作台”位置改为“文档中心”。两个替换均在 Preview 内完成，不显示对应的 AI 聊天/Agent 执行入口，个人中心不再放文档中心。交互细则见第 16 节。

## 7. 管理后台

本节“管理后台”指统一应用中平台管理员有权看到的功能集合，采用 SaaS 管理员工作台组织方式，不指独立站点、第二套前端或另一套登录。普通用户不显示平台管理菜单，直接访问管理页面或调用接口仍由服务端拒绝；项目编辑者的配置能力保留在自己的项目范围。

| 页面       | 主要内容                                     | 关键约束                                           |
| ---------- | -------------------------------------------- | -------------------------------------------------- |
| 账号管理   | 搜索、列表、创建、启停、改平台角色、重置密码 | 仅管理员；不泄漏密码、令牌或项目外成员资料         |
| 项目管理   | 项目编码、名称、说明、图标、排序、归档状态   | 编码稳定；归档不删除旧源文件，不允许普通编辑者归档 |
| 项目成员   | 搜索已存在账号、添加/移除、编辑/查看角色     | 仅管理员授权；唯一成员关系；禁止跨项目串改         |
| 客户端配置 | 编码、名称、图标、布局、顺序、启停、默认入口 | 编辑者仅本项目；默认入口必须有效                   |
| 菜单配置   | 分组、页面名称、顺序、显隐及注册页面绑定     | 只绑定受控注册页面，不输入任意脚本或外部执行地址   |
| 平台设置   | 本平台可支持的品牌/主题等稳定配置            | 不使用旧 remoteManagement 作为权限开关             |

首期原型页面由开发者编写 React 源码后构建发布。后台“添加页面”只维护菜单或绑定已经注册的页面组件，不代表可以上传 HTML/TSX 自动获得运行能力。

项目/客户端配置真实持久化，服务重启后仍存在。保存失败显示真实错误并保留草稿，不显示成功或静默回滚成默认值。并发编辑需版本冲突检测，不能后写无提示覆盖。

## 8. 原生项目包与页面注册

### 8.1 包内容

逻辑项目包包含稳定项目/模块标识、客户端声明、页面注册、路由与菜单默认值、资源、合成模拟数据和可选的演示状态适配。包不包含平台账号或会话，不依赖 Rental OS 活动目录。

源码包和后台项目记录是两个对象：前者提供可运行页面能力，后者提供名称、成员和展示配置。通过稳定模块键绑定，不能仅凭项目名匹配。没有页面模块的项目仍可以有客户端和空工作台。

### 8.2 路由与加载

页面具备稳定 projectId、clientId、pageKey；路由刷新和直达保持上下文。按项目/页面懒加载，不在首屏导入所有项目业务模块。未知模块、停用客户端和失效页面有明确处理，不执行任意远程源码。

首期只提供通用空画布与订单示例；不创建其他项目业务页。旧页面到新页面的迁移映射作为后续工作，旧 HTML 的存在不意味着可以在新产品中直接访问。

### 8.3 模拟业务边界

原型使用独立的模拟数据访问接口或前端 store，明确区别于平台真实 API。订单、客户、付款、履约等不调用 Rental OS 或其他真实业务后端。模拟数据都是合成资料，不复制数据库、真实客户、凭据或私有订单。

账号、项目和客户端切换时隔离演示状态。模拟数据不构成资金、库存、交易或真实执行结果；前端演示按钮不能触发平台授权变更。

## 10. 首期实时协同

### 10.1 在线与鼠标

- 进入项目工作台后加入该项目的在线范围；可看到同项目在线用户的展示名称、头像和稳定区分色。
- 鼠标只在项目内容区采集并广播，不共享系统桌面、浏览器界面、平台管理页或登录表单。
- 两人处于同一个客户端和页面/弹窗表面时显示对方鼠标与姓名标签；页面不同时只显示其位置上下文，不把坐标叠到错误页面。
- 鼠标移出内容区、切换项目、退出或断开后隐藏；断线不能永久留下幽灵指针。
- 鼠标高频事件可合并和限频，不能挤占页面操作消息。指针仅是覆盖层，不移动他人真实鼠标，不阻挡本机点击。
- 不保存鼠标轨迹历史或提供回放；在线状态是临时运行态。

2026-11-09 负责人补充：展示前台也保留登录后的鼠标及主动跟随。入口放在页面预览工具栏与全屏头部，不占用全站顶栏；前台与Demo使用同一项目在线范围，前台跟随后仍在 `/pages`，Demo仍在 `/demo`。鼠标限于当前可见预览，切到源码、PRD或离开项目页面后不继续显示或采集；首期不扩展首页、Docs阅读与普通表单的同步。

### 10.2 主动跟随

用户在在线列表选择某个独立操作会话 → 点击跟随 → 在自己权限内对齐其项目内页面与弹窗状态 → 持续接收更新 → 随时点击退出，恢复独立操作。

跟随不强制全员同步。未跟随的人保持自己的页面状态；不传播跟随者自己的页面回显形成循环。首期不支持跟随链与互相跟随，发现目标进入跟随/离开当前项目时结束原关系并说明原因。

同一账号多个标签页按会话/标签页区分，避免误跟随另一个窗口；服务端从真实会话确定用户身份，不相信客户端声明的用户 ID。

### 10.3 首期同步内容

| 类型         | 首期行为                                                   |
| ------------ | ---------------------------------------------------------- |
| 页面跳转     | 同项目内客户端与已注册页面跳转；目标必须仍有权限且页面有效 |
| 弹窗打开     | 同步受支持的弹窗键和安全业务标识，如示例订单 ID            |
| 弹窗关闭     | 同步关闭状态；不得通过伪造 DOM 点击完成                    |
| 刚开始跟随   | 获取目标最新页面/弹窗快照，不要求目标重新点击              |
| 断线后恢复   | 重新鉴权并获取最新快照；不回放历史点击或重复执行业务动作   |
| 不支持的交互 | 保持本地状态，不假装已同步；可在跟随说明中明确基础范围     |

首期不跟随筛选、分页、排序、滚动、普通输入及模拟业务数据变更，也不跟随平台后台表单和真实管理命令。目标当前在不支持页面或真实管理后台时不强行导航，结束/暂停跟随并保留可理解反馈。

### 10.4 操作与退出

跟随状态有清楚的目标名称和退出入口。为避免本地状态与目标互相争抢，跟随期间导航及受同步弹窗由目标驱动；本机希望独立操作时先退出。退出后不继续接受目标的操作状态，也不覆盖退出后的本地操作。

退出跟随不退出账号，不撤销项目成员关系，不还原其他人的页面。目标下线、项目归档、账号禁用、授权撤销或组件协议不兼容时安全结束跟随。

### 10.5 权限与非重复执行

实时连接和订阅分别验证真实账号及项目权限；换项目必须重新校验。鼠标和操作消息不能携带跨项目数据；权限撤销后停止下发且拒绝重连。

同步只采用受控路由和界面状态，不发送脚本、任意 URL、CSS 选择器或“按 DOM 坐标执行点击”。跟随端渲染状态，不调用真实创建、删除、授权、支付等接口。即使目标点击真实命令，也不能在跟随者账号下重做一次。

## 11. 后续完整跟随需求

保留后续支持筛选、分页、排序、Tab、滚动、普通原型表单、行展开/选择及必要模拟数据状态的方向，按页面的受控状态协议适配；不宣称任意 React 页面自动获得完整同步。

状态以项目、客户端、页面、模块版本和演示会话为作用域；需要快照、版本、顺序、回显抑制及重新加入。模拟数据变更应同步确定性状态，不在跟随端重放业务请求。

登录、密码、令牌、密钥、账号管理及平台真实写入表单始终不共享。后续新增普通表单字段必须显式登记共享白名单，不能抓取所有输入框或整份 DOM。完整状态同步尚未拆成首期实施任务。

## 12. 非功能与运行要求

### 12.1 独立与持久化

平台账号、项目、成员、客户端和菜单真实持久化；服务重启后保留。在线、鼠标和轻量跟随状态可以是临时态，服务重启后用户重新加入，不伪装成未中断。

Preview 不依赖 Rental OS 的进程、接口、数据库、配置、账号库、缓存目录或 node_modules。认证代码可以参考通用做法，但首期不接通 Rental OS 账号体系。

### 12.2 访问与资源

服务端保护项目元数据、私有文档/资源及协同通道，直接 URL 与缓存不能绕过。新产品不能无鉴权挂出旧 projects 和静态项目总清单，也不能保留旧本机/remoteManagement 绕过。

公共 UI 资源可以公开缓存，私有项目数据不能混入未授权的全站静态清单。纯前端示例源码不被当成保密机制；示例只使用可公开的合成数据。

### 12.3 性能、可用性与可访问性

首屏不加载所有项目业务代码，不加载旧 HTML/iframe 或与空工作台无关的图形库。项目/客户端/页面切换不整页刷新，不等待旧项目请求占用新界面。鼠标消息丢弃陈旧位置，页面状态保持有序。

首期至少用两名有权限用户和一名无权限用户的独立会话验证；不据此宣称大并发 SLA。性能基线在底座切片实测后记录设备、网络、数据量、加载/切换时间和消息延迟，不伪造提升倍数。

支持加载、空、失败、无权限、断线、重试与键盘操作；减少动态偏好不丢失功能。视觉验收由负责人浏览器评审，构建与测试不替代视觉验收。

## 15. Git 驱动的快速更新

### 15.1 用户流程

本地通过 AI 修改页面 → 本地检查与浏览器预览 → 提交并推送 Preview 的指定发布分支 → CI/服务器取固定提交 → 检查和原生构建 → 发布候选版本 → 校验及健康检查 → 切换正式版本 → 在线用户收到更新提示。

普通页面/样式修改无需手工远程编辑文件或停止整个账号服务。React 页面发布的是编译产物，不能只上传 TSX 当作线上页面。一个页面的修改可能影响共享资源，逻辑发布单位是完整且一致的版本；内容散列资源可以只传变化部分。

### 15.2 发布边界

- 只作用于 Preview 仓库、部署目录与服务，不能修改或部署 Rental OS。
- 发布分支、CI 提供方、服务器接入和凭据在实施中配置；功能分支的普通推送不直接覆盖线上。
- 首期快速更新面向与当前 API/协同协议兼容的前端资源。首次平台安装、后端变更和数据库迁移有单独步骤，不随每次页面提交隐式执行。

项目网址是资料入口，不是访问授权。提供项目专属的只读凭证，与普通浏览器登录、发布凭据和管理员密码分开；服务端核对凭证状态、有效期、项目状态及授权范围。具备签发权限的管理员管理凭证生命周期，原始值只在受控签发时显示，持久化仅存不可逆验证值和必要元数据。撤销后旧连接、缓存及后续读取不能继续返回正文。

外部 AI 可以通过带认证的 HTTP 读取 Markdown/JSON 及链接资源，也可以配置远程只读 MCP。入口包括项目概况、需求目录、指定业务文档、需求搜索与页面上下文；支持分批读取，不要求把整项目全文一次装入上下文。结果带当前资料版本、稳定文档标识及来源定位；搜索摘录不能替代正式原文。网页账号和 AI 凭证采用各自身份适配、消费同一发布目录与项目授权边界。

### 17.6 Git 更新、一致版本与发布边界

日常流程为本地修改原型/业务需求 → 本地验证 → 推送指定发布分支 → GitHub Actions 校验并构建固定提交 → 生成前端与允许发布的业务资料候选版本 → 服务端校验 → 一起切换。内部研发文件可以存在源码仓库，但不得出现在候选资料包中；账号、数据库、授权和凭证仍独立存储。

业务 Markdown、索引与图片放在服务端受控资料区，通过授权接口读取，不放入公开 web/assets 或全站可下载的 JS。单份发布清单覆盖页面版本及各项目的业务资料版本/散列；网页和 AI 获取同一发布快照，切换或回退不出现新页面搭配旧需求。文档修改也必须触发新版本，即使前端编译文件没有变化。

上传、路径/散列验证、权限或兼容检查失败不切换。回退只切换兼容的页面与业务资料版本，不覆盖账号/凭证库，不恢复已撤销权限。移出当前发布清单的文档不能通过旧版本 URL 继续读取。发布代码/资料与服务 API 安装升级分开，普通 Git 推送不隐式迁移数据库。

### 19.4 必须解决的合同差异

1. **项目权限与重要页面权限**：浏览器账号经任何入口读取某重要页面专属资料，都应满足第18.2节；项目文档中心及下载/图片/索引必须参与同一判定。原项目级只读AI凭证覆盖整项目业务资料的既有合同保留，但页面授权是否也要限制AI凭证须显式决策，不能暗中混用两种身份。
2. **页面身份与可见性**：权限比较应按稳定客户端/页面身份，不按数组下标。添加、移动或调换页面不能把旧公开权限套到另一页；编辑者正常添加受限页面也不应被误认为扩大公开范围。
3. **PRD唯一关联来源**：manifest负责发布白名单，后台配置只能从白名单选择关联，不能发布任意文件。建议由一个有效关联解析器同时供前台、侧窗、文档中心和AI读取；它采用“本地默认+后台覆盖”还是只允许本地关联，须在NP-19/21/24实施前收口。现有两套来源不能继续同时对用户声称权威。
4. **上下架与版本**：源码登记、构建包、页面菜单和资料清单之间必须可核对。缺少源码/资料应返回明确失败；菜单隐藏与源码移除分别处理，不通过模拟成功或默认页面掩盖问题。
5. **权限元数据范围**：前台需要显示受限页名称与锁定提示，第5.3节旧“无权不返回任何菜单名称”与之不同。公开目录应只返回当前允许列出的展示信息；整个后台项目清单不能因前台需求而自动公开。本轮发现展示目录服务返回所有未归档项目菜单，而UI在客户端过滤当前项目，需明确服务端公开清单范围。

## 25. 项目需求关系图谱（2026-11-07确认）

### 25.1 目标、范围与业务依据

前台 Docs 增加“需求关系图谱”。其主要价值是让本地开发 AI 和经授权的远程 AI 理清项目的细节业务关系，修改某项需求或原型时，找到直接与间接受影响的需求和原型位置，并能解释原因。可视化与 MCP 读取消费同一份结构化业务图谱，不维护两份相互独立的关系数据。

本平台展示业务需求和原型，不是实际业务系统。图谱纳入项目全部有效 PRD 中的需求，包括尚无原型的功能及没有关联的独立节点。页面关联指对应的 React 原型页面、组件、弹窗和交互；接口及外部平台可以作为 PRD 中的业务概念，不意味着平台已完成真实接口、数据库或业务对接。Preview 的研发四册、个人开发记录、协作接续和凭据不进入对外业务图谱。

以负责人已确认的 PRD 为业务依据。原型呈现与 PRD 不一致时记录差异，向负责人确认，不能为匹配原型擅自改写需求，也不能自行解决相互冲突的 PRD。草稿、规划、已确认、待核实和废弃内容保留各自状态，不能混作有效业务规则。

### 25.2 主题圈与唯一节点

2026-11-10负责人补充：需求先按业务线分类，同站租还、甲租乙还、门市租赁、公务车、租车券专项分别提供入口；车辆管理、车行门市与据点、会员企业、调度、价格行销、合约配额、统计、通知及账号权限归入共用管理。分类内区分业务流程与状态、管理功能、关键规则、业务对象与接口。共享需求保持唯一节点，可从多个相关分类找到；业务逻辑和管理功能关联保留明确含义，分类归属本身不产生业务依赖。

2026-11-11负责人修正展示方式：不再以分类页或分类树作为查看图谱的前置入口，直接呈现获准需求及真实关联，通过节点和关系图例点选显隐。业务主题仍作为数据归属和右侧参考信息，不能将同类归属当作依赖。重点表达功能逻辑、功能关联、数据流转及平台接口关系。左侧搜索具体需求，右侧查看要点、上下游、原文和影响；选择后突出直接关系，其余内容保留空间参照。

图谱保留与其他文档页一致的顶部导航、网站左侧菜单和文档面包屑；项目切换统一放在网站侧栏，图谱内部不重复。按实际内容宽度调整栏数，手机沿用公共导航抽屉，只有主动全屏时临时覆盖外壳。原文可定位相应章节。浏览器无法启用3D时提示切换2D，不模拟成功。

同一节点可以属于多个主题，但保持一个稳定身份。每个节点指定主要主题；同一画布只绘制一次，右侧标明其所属主题。筛选任一所属主题都能找到该节点，邻接聚焦可展示跨主题连接。同属一个主题是归属信息，不代表存在依赖、数据流或其他业务关系；布局位置和相邻距离也不能被 AI 解释为业务事实。

### 25.3 业务细节和关系依据

图谱细到业务层：功能需求、业务对象、关键状态、关键字段、业务规则、流程步骤、接口约定和外部平台均可成为节点。拆分以影响分析是否有意义为准，不机械将每段文字、每个 UI 标签或所有代码函数转换成节点。

每个节点保留稳定 ID、名称及必要别名、类型、主题归属、有效状态、业务说明和 PRD 出处。原型覆盖分为“尚无原型、部分呈现、已呈现”，关联页面及可定位的组件、区块、弹窗或交互，并说明覆盖和遗漏；“已呈现”只表示原型覆盖，不代表真实业务功能已开发或视觉验收通过。

关系保留源/目标节点、方向、业务含义、影响如何传播、PRD 章节或段落、依据摘要及对应资料版本。应表达具体细节，例如某字段由哪一平台提供、哪些状态触发哪条规则、规则约束哪个操作、哪个原型交互呈现该规则。引用整份 PRD 但无法定位实际依据时，不将关系标为已核实。

2026-11-08负责人调整：对外图谱和 MCP 是正式业务资料，关系只能有明确 PRD 原文依据，不设置推断或待核实关系。作者合同只允许 explicit；不能通过改标签将无依据的关系变成明确关系。依据不足或冲突先在本地需求沟通和内部开发记录解决，确认并补齐出处后再写入业务图谱。

“业务关系”“主题归属”“需求由原型呈现”分别表达。语义相似不等于业务依赖。旧关系发生变化时保留演变依据；需求废弃后保留废弃节点及历史关系，默认隐藏，仅在历史查询中返回，不进入当前有效影响链。

### 25.4 本地 AI 强制维护与过期提醒

图谱必须随日常需求沟通、PRD 编写和原型开发维护，这是强制开发要求。每次新增、修改、删除、重命名需求或原型，AI 必须检查受影响节点、业务关系、出处、原型覆盖和相关差异，并同步维护。若确认不影响图谱，仍记录本次核对范围及结论，不能跳过维护。

分析在本地开发工作流程中完成，使用当前 AI 助手或负责人配置的模型；“本地执行”不代表必须内置或运行本机模型。平台网页和线上 MCP 不进行在线 AI 建图、不编辑关系，不新增默认全仓扫描或上传私有资料的流程。图谱和已登记业务资料随 Git 发布。

跟踪 PRD、原型关联及维护核对的内容版本，发现未覆盖的新增需求、出处已变化、页面已移动或删除、相关原型未核对时标记维护缺口。未确认的关系不进入对外图谱；“图谱未同步/依据过期”仍作为资料维护提醒。前台显示清晰提醒，并列出当前用户有权查看的待同步范围。

负责人明确：图谱未同步或引用失效不阻止部署，不设置因此失败的 GitHub CI 发布门禁。MCP 同步返回过期状态、未覆盖范围及读取限制，不能在缺口存在时返回无条件的“无影响”。此规则仅针对图谱维护质量，不放宽既有权限、路径、资料隔离及发行完整性约束。

### 25.5 AI 查询与影响分析

单独授权的项目 AI 可通过只读 MCP 读取其获准项目的完整业务需求图谱，包括尚无原型的需求。支持读取图谱概况、主题、稳定节点详情、邻接关系、来源需求及原型覆盖；可按名称/别名/类型搜索，查询两项之间的关系路径，以及某项变化的直接和间接影响。

影响结果按业务关系含义和方向遍历，而不是将所有连通节点、同主题节点或相似节点都列为受影响。结果沿明确关系区分直接与间接影响，说明传播路径和每一步依据；依据过期时保留核对提醒，不输出推断或待核实关系。列出需要一起核对的需求和原型位置。历史节点默认不参与有效影响查询。

工具返回结构化、可分页的结果，包含项目身份、图谱/资料版本、稳定节点与关系 ID、出处、原型覆盖、证据状态、过期状态和覆盖缺口。限制遍历深度与结果量；截断、未读取和资料缺失要显式返回，不能以空结果表示全部无影响。需要特定修改内容才能判断时，AI 继续确认修改场景，不承诺凭一个功能名能穷尽全部影响。

MCP 只提供业务需求和原型覆盖定位，不开放内部研发四册、任意本地路径、运行数据库、凭证或写工具。对外页面定位使用受控页面身份和业务锚点，不默认暴露本机绝对路径或平台内部源码。

### 25.6 网页权限与界面

网页按现有用户权限展示可读业务需求和原型关联；独立项目 AI 凭证按管理员明确授权的项目业务范围读取，不能与浏览器会话共用身份或仅依赖前端隐藏。无原型需求需要明确的业务资料访问范围，不因为缺少页面自动公开，也不因暂无页面阻止已获项目业务授权的 AI 读取。
