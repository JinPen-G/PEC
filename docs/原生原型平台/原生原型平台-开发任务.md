# 原生原型平台开发任务

当前新增授权为需求第30节的10/30分钟休息播放器，随后追加前台入口、首页少量精选与旧示例分组纠偏，并要求提交上传。既有安装条、图谱及Docs阶段已在`c39d811`提交上传；本阶段不扩大业务迁移或手动部署范围。

## 休息播放器实施

- 实现入口：`apps/web/src/features/rest`，由全站身份宿主提供单一Provider，前台、Docs、Demo与后台共用。真实Audio、文件URL和绝对截止时间由独立控制器管理，大小播放器不各自创建音频；身份修订、登录/退出或应用卸载释放播放器。
- UI边界：指定本地UIARC的MediaPlayer、NowPlaying及共享动效原语共12文件原样冻结；保留来源与哈希，不进入Registry。与平台动效偏好的差异通过构建适配解决，不修改上游内部样式或逻辑。
- 音频边界：已按负责人授权，从PM对话定位所给MP3和官方封面，复制到Preview本地媒体槽位并验证SHA-256一致。30分钟单曲循环，10/30到期停止，暂停和定位不重置截止时间；选择本地音频与恢复默认曲目均不延长休息，文件不通过协同或管理接口上传。音乐/封面不提交Git，构建副本发布前单独确认授权。
- 正式服务：保留原公开资源和真实路径边界，为构建内MP3提供正确类型、HEAD、单段Range与流式响应；不只依靠Vite播放验证。分段、后缀、不满足范围和路径越界需独立反例测试。
- 需验证：状态机、延迟播放结果、自动播放拒绝、换源释放、计时与循环、StrictMode和宿主卸载；真实浏览器检查大小切换、页面切换、播放器控件、全屏、手机暗色、减少动效、到期及退出。具体通过项进入本阶段记录，不将测试音频算作指定歌曲验收。
- 图谱核对：本功能是平台个人工具，不改变RIMO或组件中心业务页面、PRD原文、节点关系和覆盖位置；保持业务graph.json，不执行全量review。

首页精选通过`module.pages[].featuredOrder`登记1–6的唯一顺序，服务端只为获准可见页面投影该字段，前台再限制公开项、当前项目和最多6张。RIMO选用车型组、门市订单、车辆排程、动态调价、公务订单、租车券；迁移登记脚本保留已有精选，不改菜单或权限。Gallery近视口加载、离开卸载，链接与内嵌预览分离，避免嵌套链接。旧两页的本地分组已备份后对齐“营运端 · 车辆管理”，正式区块源码保留。

最新生效范围见需求第20/21节与任务第16/17节：多项目基础信息、项目菜单与用户授权；后台统一复用 Rental OS 原组件，旧HTML挂载已退役。早期阶段说明不能覆盖本轮明确要求。

版本：1.5。更新日期：2026-11-06。状态：前台、后台基础配置及业务资料服务已有实现；本轮需求/源码复核发现后台管理闭环与权限缺口，详见第15节。NP-21至NP-29有部分代码及定向证据，不能再称全部尚未实施；生产部署及负责人视觉/功能验收仍未完成。需求唯一来源为[需求册](原生原型平台-需求.md)，证据见[开发记录](原生原型平台-开发记录.md)，下一入口见[协作接续](原生原型平台-协作接续.md)。

实施内容：

1. 核对 Preview 现有 React/Vite/TypeScript、根依赖和本地未提交成果，建立可还原的本轮基线，不清理未知文件。

- 审核版本、可解析包声明及 React 单实例要求；不复制 node_modules、锁文件、.env、真实数据和运行配置。

验收：Preview 可以脱离上游目录安装/构建；来源可核对、无 Rental OS 代码变更或进程依赖；升级/回退只在 Preview 发生。

## 5. P1：真实平台

### NP-03 前端底座和壳

将主题、字体、圆角、间距、图标、按钮/表单/表格/反馈、动效偏好及 SaaS 平台管理员式的框架接到 Preview 公共入口。统一外壳通过明确 props/context 接收项目、客户端、菜单、用户、真实角色/权限结果和命令，按角色生成平台管理或项目菜单，不引用 Rental OS API/authStore/租户/订阅/Copilot。

右上角原 Copilot 位置渲染“本页文档”动作，接收当前页面的文档可用性；原 Agent 工作台菜单位置渲染“文档中心”，按项目阅读权限可用，不继承 AI capability 或订阅门槛。个人中心不增加文档入口。壳不承担读取任意文件路径的逻辑。

保留原版交互、键盘、ref、nullable、禁用、异步失败和关闭生命周期。对 Tailwind/构建插件/样式作用域与 Preview 现有工具链逐项适配，不能整仓升级来掩盖兼容问题；需要升级时说明影响并仅修改 Preview。

验收：同一 Preview 应用可显示系列一致的壳、主题和基础控件，管理员/普通用户菜单按真实上下文切换；浅深色、窄屏、减少动态与真实错误状态可验证；不新增后台前端，不填占位仪表板。

### NP-04 存储、登录与会话

实现持久化账户和会话、凭据验证、登录/退出、读取当前身份、本人改密、会话失效和撤销。密码用成熟密码散列能力，不记录明文。建议浏览器采用受保护的会话 cookie 和写请求来源/CSRF 约束，具体方案在 NP-01 收口，不复制上游 localStorage token 协议。

管理员与普通成员共用登录接口、cookie/会话与身份上下文；登录角色只从服务端读取，不接受客户端切换身份。刷新、角色变更及账号切换重新校验上下文，平台管理权限撤销时移除菜单并安全离开无权路由。

会话标识、数据库连接和密钥留在独立环境配置，不能写进前端包或来源清单。登录限制、有效期、错误信息与日志脱敏在技术记录中明确。

验收：错误、过期、撤销、重启和并发请求行为明确；不接受客户端伪造用户/角色；没有“本机自动管理员”绕过。

### NP-05 账号管理

实现管理员初始化、创建/查询/启停账号、设平台角色、重置密码和必要的首次改密流程。账号唯一性由持久化约束保证；最后一个有效管理员不能被并发停用或降级。

管理员操作保留最小审计：操作者、目标、动作、时间、结果；不记录密码或会话秘密。对历史关联使用停用而非随意硬删除，具体保留策略在存储设计落定。

验收：所有管理命令服务端鉴权，失败反馈与实际结果一致；普通成员无法通过改请求提升平台角色。

### NP-06 项目成员与授权

平台管理员拥有全局管理权限。普通账号通过唯一的 userId/projectId 成员关系获得 editor 或 viewer；成员状态与项目状态共同决定访问。

建立一个被 HTTP 与实时通道共同消费的授权入口，覆盖清单、单项目、客户端、菜单、资源和在线房间。客户端所属项目必须与 URL/上下文一致。编辑者可以维护本项目配置，不能管理成员或平台账号。

查询缓存、异步请求和 UI 状态带会话代次及项目范围；切换、撤权和退出后晚到响应不能落回新上下文。实时连接必须能感知禁用、撤权和项目归档。

验收：至少两个项目、不同成员角色和无权限账号验证真实拒绝；前端隐藏不替代服务端检查。

### NP-07 管理后台

实现账号、项目、成员、客户端、菜单和必要平台设置的真实管理页。统一列表/表单/弹窗/异步命令，范围与角色遵循需求矩阵。

这些页面全部注册在同一前端 Router/外壳中，作为管理员直接可见的导航分组；项目编辑者只在自己的项目导航中看到配置能力。不能再生成“进入后台”登录入口或依靠 Ctrl+Shift+M 等隐藏快捷键。管理员可在应用内进入项目并返回管理导航，使用同一会话。

项目编码与客户端/页面键稳定；默认入口和菜单绑定通过校验；归档/启停不删除旧 HTML。保存采用修订号或等价并发检查，冲突提示重新读取，不默默覆盖。

验收：管理员配置项目与授权后普通账号可见，重启后配置保留；编辑者跨项目和授权动作被拒绝；查看者只能浏览配置结果。

### NP-08 工作空间和路由

实现统一登录、角色落地、获授权项目列表、项目切换、客户端切换及注册页面路由。根入口先校验身份，管理员默认进入项目管理页，普通用户进入获授权项目列表。项目/客户端路由可保留 /p/{projectId}/{clientId} 前缀，但不能继续用旧 HTML 目录作为新入口。

平台管理页面可有应用内部逻辑路由分组，不代表第二站点或第二登录页；路由与 API 均检查平台角色/项目范围。恢复上次页面或处理登录 returnTo 时重新验证角色和项目，不把普通用户导航到管理员旧地址，也不因管理员进入项目而丢失其平台管理导航能力。

无项目、无客户端、空工作台、失效入口、无权限和加载失败分别处理。账号/项目切换清理旧范围，默认入口选择不跨项目。旧链接保持原样留存，不未经清单分析强行映射成新订单页。

验收：统一入口下管理员/普通用户的登录落地、刷新、直达、返回、角色变更与账号切换正确；普通用户直达管理路由/API 被拒绝；空内容区无旧 HTML 请求、iframe 或虚构业务卡片。

## 6. P2：原生包、订单页与文档

### NP-09 包合同与注册器

建立类型明确的 ProjectModule、ClientModule、PageDescriptor 和演示适配接口，源码模块与后台 project 通过稳定 moduleKey 绑定。后台只能绑定已注册能力，不能上传字符串当 React 源码执行。

注册器按模块/页面懒加载。提供 empty-canvas 基础能力，未接入业务页时直接空画布。模拟数据提供独立接口，不能使用平台真实授权服务充当租赁业务 API。

验收：新增逻辑项目包不修改壳；项目不必有业务模块也能建立工作空间；重复键、无效模块和未注册页面有拒绝/错误处理。

### NP-10 通用租赁订单列表

按固定来源适配 RentalOrdersPage、样式和必要列/展示模块；不复制 Rental Core 服务、整份业务 API 或真实账号状态。

首期提供确定性合成订单数据、本地筛选/分页/排序/列显隐/选择/刷新以及只读详情层。真实新建、支付、押金、分配、取还和结算不实现，保留入口须说明范围，不能弹空成功。

提供稳定的详情层键与订单 ID，记录可共享的轻量状态。跟随详情不受跟随者本地表格筛选影响。订单示例所在项目/客户端名称由配置决定，不硬编码成唯一真实项目。

验收：网络侧没有真实租赁调用；原生组件和合成数据可独立运行；负责人可在浏览器评审界面，与原来源对齐程度单独记录。

### NP-19 项目文档与页面关联服务

复用现有 project-core 文档扫描/安全路径能力的可用部分，接入正式项目授权服务。目录、正文、图片与互链都经账号和项目检查；源目录由管理员在受控配置中指定，编辑者只能维护本项目页面关联，不能提交任意服务器根路径。

共享合同加入 DocumentSource、DocumentEntry、PageDocumentLink。关联键为 projectId/clientId/pageKey，可引用文档及锚点，不依赖旧 HTML 目录或 DOM。原生声明默认关联与持久化覆盖区分，显式解除关联不能被默认值重新补回。读取现有配置前验证标识和目标，首期不批量修改旧关联文件。

文档源是只读内容；配置/关联真实保存并有并发修订。不得在读取失败或 401/403 时回退公开静态内容，不能直接沿用旧客户端的 JSON→静态文本兜底路径。账号/项目切换和撤权清理读取缓存，过期响应不能显示到新上下文。

支持 Markdown 目录、正文和允许的相对图片类型，保留内容清洗、路径/真实路径边界和缓存版本。项目资料与前端发行目录分离，不把真实 PRD 编进所有人可下载的全站包。无文档、无关联、丢失、失败、无权限分别返回真实状态。

验收：用合成 Markdown、图片、互链、标题与 Mermaid 夹具验证目录和正文；跨项目、资源直达、编码越界、符号链接逃逸、撤权及静态兜底绕过均被拒绝；旧 HTML/PRD 原文件没有被改写。

### NP-20 Copilot 式侧窗与菜单文档中心

在 Preview 内按固定来源复用 Copilot 的侧窗 DOM/布局、桌面停靠与内容区收缩、窄屏覆盖、开合与减少动态规则，保留来源和许可。只把聊天内容替换成文档阅读器，不依赖聊天 Provider 或模型。旧 PrdReviewPanel 的阅读逻辑可抽取复用，不能连同其悬浮拖动/模式切换外壳一起保留成第二种侧窗。

“本页文档”根据当前原生页面绑定打开文档，支持标题目录、正文搜索、锚点、相对图片、文档互链和 Mermaid；切页更新关联，关闭不重置原型。无关联入口有解释，关闭/焦点与窄屏背景交互可用。

文档中心替换原 Agent 工作台菜单，位于同一 Router/外壳内，不放个人中心。保留项目目录分类/过滤、阅读、标题大纲、链接直达与返回原型，项目切换按真实授权过滤。DocsCenterPage 现有 useHtmlPageCatalog 等依赖改为原生页面注册及页面关联，不为查看 Markdown 重新开启 HTML 扫描。

MarkdownReader 等现有安全阅读能力优先复用，图形依赖按需加载。首期阅读状态独立于轻量跟随，不能通过协同消息传播文档正文或绕过授权。示例订单可关联一份合成文档验证，不复制真实客户 PRD。

验收：A-19/20 全部通过；两个入口及右侧窗在浏览器评审位置和风格正确，个人中心无文档中心，界面无 Copilot 聊天/Agent 执行残留，且 Rental OS 没有任何修改。

## 7. P3：轻量协同

### NP-11 实时鉴权与在线房间

采用适合双向低延迟消息的独立实时通道，协议与实现库在 NP-01/本任务中固定。HTTP 登录身份映射到连接与标签页会话；订阅必须再次检查项目和当前账号状态。

每个连接只加入明确项目范围。项目切换、禁用、撤权、归档和断线均移除连接；心跳/超时值配置化。在线信息只投影显示名称、头像、会话标识和必要的位置，不下发邮箱、电话、token 或别的项目。

验收：第三个无权限会话无法订阅；撤权后旧连接不能继续接收；短暂网络抖动不产生永久幽灵成员。

### NP-12 鼠标与表面映射

在注册的内容表面采集指针，外壳、管理页与登录页不采集。消息包含稳定 surface/page/dialog 上下文和位置，不传整份 DOM。

优先使用内容表面的相对坐标/可见锚点，按滚动与容器映射；视口不同不承诺像素级复刻。不同页面或未打开同一弹窗时隐藏该位置。高频移动合并，保留最新位置，网络排队时丢弃过期坐标。

验收：两个有权限会话在正确表面看到姓名指针；移出、换页、换项目和断线及时隐藏；覆盖层不拦截操作。

### NP-13 页面/弹窗适配协议

原型运行时显式提供 getSnapshot、subscribe、applyRemoteState 和 dispose；首期状态只包括 clientId、pageKey、允许的弹窗键/安全参数、版本与序号。

页面导航和详情层开关发布语义状态；接收端通过受控组件状态呈现，不 dispatch 合成 click，不调用业务 mutation。远端应用设置回显标记，不能再广播同一个远端变更。

未实现适配的交互保持独立，不能宣称全页面跟随。后续普通表单同步通过新增 schema 扩展，密码和平台管理命令不进入 schema。

验收：路由、详情打开/关闭、首次快照与不重复执行有定向测试，原型运行时不依赖订单业务专有字段。

### NP-14 跟随协调与恢复

用户主动选目标并开启，服务端验证同项目、有效页面和独立目标会话。保存最小最新状态与版本，加入时给快照，不存或回放所有点击历史。

拒绝跟随自己、互相跟随和跟随链；目标开始跟随其他人或离开项目时结束原关系并反馈，不隐式转发到第三人。跟随端页面/弹窗由目标控制，退出后恢复独立操作并忽略旧消息。

消息带来源会话、项目、协议、模块、序号/修订号；乱序与过期消息拒绝，重连先重新鉴权再取最新快照。会话变更或模块不兼容安全结束，不循环刷新或重复执行。

验收：两人协同及第三人独立状态、主动退出、目标离线、换项目、撤权、重连、中途加入、消息乱序和版本不兼容全部覆盖。

## 8. P4：构建、Git 自动发布与交付

### NP-15 原生发布产物

建立独立原生构建入口，不能复用默认打包真实 HTML 项目的结果冒充原生发行版。应用运行不依赖上游源码目录和开发服务器。

产物清单至少包含：releaseId、Preview commit、UI 来源版本、原生模块目录版本、API/协同协议兼容范围、构建时间、文件路径/大小/散列。资源使用稳定内容散列或版本路径，版本入口与资源集合一致。

平台运行配置、密钥、数据库、上传/持久化目录和日志不进前端产物。纯前端订单数据只用允许公开的合成样例。

验收：脱离 Rental OS 可复现构建，清单完整，不含旧 HTML、客户资料、凭据和跨目录依赖；前端页面修改经过构建才发布。

### NP-16 Git 自动发布和回退

负责人已选择推送 Git 后由服务器/CI 自动部署。只监听明确配置的发布分支/标签，功能分支不覆盖线上。具体 CI 提供方、仓库访问与服务器接入在该任务配置，不在 Rental OS 创建工作流。

流水线顺序：检出固定提交 → 安装锁定依赖 → 检查/测试 → 原生构建 → 校验产物 → 上传候选版本 → 服务器校验 → 健康检查 → 原子切换 → 发布版本标识。失败保留当前版本，不能先清空正在服务的目录。

相同提交/事件幂等，发布互斥；旧任务晚完成不能覆盖更新版本，必须定义分支最新提交或明确发布序列的选择规则。密钥来自 CI/服务器配置，不进入仓库、前端、日志或协同。

首期快速更新以兼容现有 API 的前端页面/样式为主；首次服务安装及 API/数据库结构变化有独立步骤，不因每次推送自动迁移数据库。平台持久化资料与 release 目录分离。

保留至少一个可用旧版本及其被打开页面需要的静态资源；回退切换到兼容旧版本，不把代码回退当作数据库回退。客户端检测到新版本后提示，避免无条件刷新正在填写的真实管理表单或正在跟随的会话。

验收：用测试目标验证一次成功发布、一次失败不切换、一次连续提交防旧覆盖和一次兼容版本回退；没有正式环境授权不部署生产。

### NP-17 综合验证

建立可重复的账号/项目/客户端夹具，至少覆盖管理员、甲项目编辑者、甲项目查看者、乙项目无权限者。真实平台请求与模拟订单请求在测试中可区分。

HTTP/实时均验证越权、失效会话、撤权、账号切换、客户端归属、直接链接、静态资料与并发保存。协同验证不复制真实管理命令，不把回显形成循环。

同一登录页分别登录管理员、编辑者、查看者，验证角色落地和菜单差异；普通成员直达管理地址/API 仍被拒绝。覆盖同一浏览器管理员退出后成员登录、管理员降级、登录后恢复旧管理地址和管理员在项目/平台导航间往返，确保没有残留菜单、第二次登录或身份自选绕过。

加入页面文档侧窗、菜单文档中心、文档源/绑定权限、Markdown/图片/互链直达、原生注册无 HTML 依赖、切换/撤权/晚到响应和禁止静态兜底的测试。文档 UI 的局部状态不应被首期业务轻量跟随错误同步。

### 13.1 正式入口、存储与身份

- apps/api/main.mjs 仅装配正式平台服务；project-core/native-platform拥有SQLite、账号、成员、配置修订与文档路径规则，platform-server拥有HTTP/SSE，contracts维护协议，client维护无静态兜底的请求。

### 14.1 项目源码、业务资料与内部记录分层

拟采用两个按稳定键关联的入口：`apps/web/src/project-modules/{moduleKey}/`维护React页面、模拟模块和项目局部样式；`project-content/{contentKey}/`维护可发布业务资料。现有`features/orders`示例保持原样，不为目录统一擅自搬动既有代码。`moduleKey`标识源码模块，`contentKey`标识业务资料包，持久化`projectId`继续标识平台项目；显式绑定，不按名称或数据库随机ID推断资料目录。

业务包示意：

```text
project-content/{contentKey}/
├─ manifest.json
├─ overview.md
├─ requirements/
│  └─ {业务分类}/{业务需求}.md
└─ assets/
   └─ {说明图片}.png
```

manifest声明schemaVersion、contentKey、moduleKey、概况文档、需求条目及页面关联。需求条目有稳定id、title、分类、业务状态、相对path、允许的图片和clientId/pageKey/anchor关联；发布文件必须明确列出。真实业务分类/文件名按项目来源保留，不要求业务PRD改成研发四册。项目私有开发记录留在内部docs或其他内部源码位置，不放进这个可发布包。

manifest和需求路径以纯数据处理，不执行文件中的脚本或Prompt；页面代码通过编译时注册器加载，业务资料不接受运行时TSX/HTML。机器概况与索引只从已声明业务文档生成，不扫描整个源码仓库补全背景，不引入AI生成摘要作为权威原文。

### NP-21 原生项目与业务资料包合同

在platform-contracts建立运行时校验和类型声明，在project-core建立包身份、文件与关联验证。新增内容键时核对store、HTTP、client与管理配置的生产者/消费者；仅管理员可绑定受控资料包，编辑者原页面关联权限不能获得任意目录发布权。

验证重复键、非法路径、重复条目、模块/客户端/页面不存在、正文缺失、标题锚点失效及资源关联。支持一页多需求与一需求多页。业务“未确认/规划/历史”等状态来自文档声明，不能依据个人研发任务状态自动推断。

### NP-22 发布白名单与内部资料排除

### NP-23 项目AI只读凭证生命周期

手机切换闪烁修正：DevicePreview 保持同一个定位内屏与内容缩放层，外框、内屏留边、逻辑宽高、缩放及页面内距同时使用 smooth 过渡。桌面高度采用预览容器的实际内高，全屏采用宿主的可用高度，隐藏Tab保留最后有效宽度；不在切换时将普通文档流突然改为绝对定位，也不使用auto高度跨状态动画。验证需覆盖逐帧非零高度、持续可见和原型DOM身份。

补充回归收口：桌面画布去除外层大留白，内层保留24px阅读内距；统一scaler建立layout/paint包含块，保证scale(1)也约束原型fixed遮罩与弹窗。车型组弹窗最大高度依当前逻辑屏幕高度计算，内容长时只滚动弹窗。FullscreenPreview按真实DOM归属识别移动原型树的点击/焦点，阻止误判外部导致退出；存在业务弹窗时Escape先交给业务弹窗。目录共用toc-position，在达到真实页底时选中最后一项，短而无滚动的文档仍使用正常标题阈值。

目录响应与页底路由稳定：useTocNavigation统一原型/指南目录，用280ms enter曲线控制单一页面滚动，目标按真实页底夹紧且点击立即选中。重复点击、手动wheel/touch/滚动键、路由切换或卸载取消原过渡；旧completion不能干扰新目标。内部路由Link在capture阶段先取消旧滚动并重置至顶部，再允许路由提交，避免旧短页夹紧scrollTop后回跳。SidebarSelection的观察器不再随children引用重建，Resize/childList按帧合并，几何取0.1px精度避免微差反复重启弹簧；菜单仍用同一高亮节点和既有morph参数。

右侧目录动效补充：TocSelection以同一指示条和列表局部数值坐标使用snappy弹簧，页面滚动与目录过渡分别控制。原型详情与Docs共用组件，点击立即选中逻辑仍保留，但视觉指示条不能直接跳到目标；减少动效分支直接定位。
