# Preview 需求

版本：1.0。确认日期：2026-11-05。依据：本次负责人逐项确认的产品目标及“先整理代码和工程治理规范，现在就做”的当前指令。

## 产品目标

将现有 Preview 演进为完整的原型管理工具，提供前台、管理后台、账号和项目授权。默认由统一服务器保存项目和文件，用户远程登录；在本地运行时，也可读取运行机器上的目录。Electron 是考虑中的交付方向，首期范围尚未确认。

这不意味着当前已具备这些能力。当前代码的本地服务、静态评审、项目扫描、菜单、文档和 HTML 承载作为既有基础保留，具体实现证据查开发记录。

## 已确认的使用方式

- 用户登录后看到分配给自己的项目列表，选择项目进入原型演示。
- 项目、原型、账号和权限在独立管理后台配置。
- 后台可上传原型页面，也可读取服务所在机器上的指定 HTML 目录；本地运行时相应读取本地目录。
- 继续使用现有 Preview 的项目和原型能力，管理后台计划复用 Rental OS 的框架和整套 UI。
- 项目内业务内容不因后台框架迁移被重写。

## 角色与项目范围

| 角色       | 已确认职责                                               |
| ---------- | -------------------------------------------------------- |
| 管理员     | 创建账号、配置项目、分配项目权限、管理原型来源           |
| 项目编辑者 | 维护授权项目的原型及相关配置，具体动作边界待实施设计细化 |
| 查看者     | 浏览分配给自己的项目                                     |

所有普通账号只能访问被分配的项目。项目编辑者的账号管理权、授权权以及是否允许同一账号在不同项目具有不同角色，尚未确认，不由整理任务补充成正式业务规则。

## 当前已授权阶段

本阶段只进行工程代码与治理规范整理：学习 Rental OS 的长期规则与工程文档规则，建立适合 Preview 的单一入口、四册、代码边界、验证命令和追溯方式。

本阶段验收：现行文档可导航且链接有效；旧文档原文可追溯；规范与实际代码一致；检查命令可运行并说明覆盖和副作用；实际代码整理保留既有行为；不覆盖已有 WIP。

## 待决策与后续边界

账号/会话方案、数据库选型、详细授权矩阵、原型上传包格式与限制、文件隔离策略、服务器部署环境、旧项目/旧链接兼容和 Electron 范围尚需产品化实施设计。

本轮没有实施账号、数据库、Rental OS UI 迁移、服务器发布或 Electron 打包，不将工程规范写成这些功能的交付证据。助手此前提出的技术建议，未经负责人确认的细节不作为已批准要求。
