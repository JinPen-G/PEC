# 原生页面接入

当前可用入口是已有原生注册器与订单示例。新增原生项目包、业务资料包及远程AI读取按[正式需求第17节](../../docs/原生原型平台/原生原型平台-需求.md#17-项目原型业务需求与远程-ai-读取)和[任务第14节](../../docs/原生原型平台/原生原型平台-开发任务.md#14-新增阶段设计与实施任务)开发，尚未实现；下面新增目录是设计约定，不是已生成的可运行脚手架。

项目业务页面使用 React。收到 HTML 后，在独立页面目录保留来源记录，再把结构、样式、资源和交互转换为 React 组件；不通过 iframe 或运行时 HTML 解释器承载业务。

1. 在 apps/web/src/features 下增加按业务职责命名的目录，页面组件用 PascalCase，纯数据/模块用 kebab-case。
2. 模拟数据和查询放独立纯模块，不调用 Rental OS 或平台账号/授权 API。
3. 在 packages/platform-contracts/src/native.js 注册模块键与页面键，在原生注册器绑定懒加载组件。服务端的注册页面校验必须消费同一清单。
4. 管理员创建项目，绑定已注册模块；在项目配置里设置客户端、菜单和文档关联。平台外壳无需为业务字段修改。
5. 有需要共享的页面/弹窗时，显式扩展 presentation 协议校验并测试；不广播任意 DOM、点击或管理表单。
6. 保留 HTML 来源、许可、资源清单和转换范围，验证桌面/窄屏、主题、键盘、减少动效、路由直达与接口边界。

已有页面范例：apps/web/src/features/orders；接入口：apps/web/src/features/prototypes/native-registry.tsx。原始 HTML 和真实项目资料不批量修改。

## 后续项目组织约定

新项目直接开发React原型，不要求另存HTML。拟将项目源码放在`apps/web/src/project-modules/{moduleKey}/`，页面组件使用PascalCase，纯逻辑/数据文件使用kebab-case；可发布业务资料放在`project-content/{contentKey}/`，用manifest明确绑定源码模块与业务文档。已有features目录不为命名统一自动搬迁。

业务资料包包含manifest、项目概况、按真实业务分类组织的Markdown PRD和允许的说明图片。业务需求使用稳定requirementId，与客户端/页面键关联；保留所属项目自身的业务文档组织，不强制套用研发四册。manifest中的标识、关联、白名单、真实路径和资源必须通过校验后才能发布。

Preview需求/任务/记录/接续、个人开发记录、AI协作过程、原型来源与迁移审计均是内部资料，不放入业务资料包。不能因为AI需要背景就把内部docs、整个仓库或全部聊天发布出去。访问凭证、账号库和环境配置另行留在服务端私有存储，不提交或打包。

网页与远程AI消费同一份已发布业务文件；正文只读，本地改动通过GitHub CI与页面同版本发布。业务Markdown和图片由授权服务读取，不放在公开web/assets中。远程AI使用项目专属只读凭证，不使用管理员密码或匿名网址。

旧HTML转换时仅在Preview保留必要来源证据，再将区段中的结构、样式、事件和状态转换为React。原文件保留；公共外壳沿用Preview，业务内容按来源复刻，Vue/Element Plus、CDN、直接跳转、图表及定时器逐类适配。先验证代表页再覆盖指定清单，不将现有原型表现自动认定为正式PRD或真实业务服务。
