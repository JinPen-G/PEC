### 发现与处理

原工程已有领域核心、协议、客户端、Node 服务、MCP、Vite 和 React 分层；没有根共用治理入口。旧组件文档保留了已不存在的组件名，测试指南描述了实际套件未覆盖的场景，并提到不存在的 audit:all；部分文档将远程默认只读描述成不带条件的结论。

整理前 `npm run lint:core` 退出码 0；`npm run format:check:core` 退出码 1，报告 148 个文件的格式差异。此前已有的类型检查退出码 0，仅代表当时 React 类型检查。

本阶段创建共用规则、文档导航和平台建设四册；归类公共资料；建立代码规范和模块导读，区分当前演示平台与已确认但未实现的产品化目标。旧文档原文字节及 SHA-256 保存在[快照清单](../历史归档/工程治理整理/2026-11-05/manifest.json)。

分层检查发现 React 直接使用了 project-core 中的三个浏览器安全模块。将上下文算法、繁简映射与语言桥脚本文本移至 project-shared，旧文件保留 re-export；React 改为引用共享包，Node 文件与传输职责不变。固定 vendor 清单是现有明确的数据依赖，检查器只允许该具体源文件读取该具体清单，不泛化豁免路径。

统一自有代码格式和行尾，新增 .gitattributes，第三方源码与历史快照禁止 Git 文本归一化。补齐七个模块导读与必要入口职责注释；清除现行组件/测试文档中与代码不符的声明，不改原型业务。

新增文档、层间导入和脱敏样例检查，quality:core 统一组合这些入口。Vite core 模式使用 examples、空挂载与固定设置，禁用 .env 目录加载，输出 output/core-build，不覆盖 dist。正常开发与构建继续使用原路径。服务打包脚本原本复制整个 packages，因此新共享包会随服务源码一并包含；本轮未执行服务打包。

### 已知边界

现有 ClientLoginPage 的表单提交直接导航，尚无真实认证；remoteManagement 是远程写入开关，尚无账号/项目权限。静态产物包含可直达的项目内容，不能用菜单隐藏作为访问控制。

本轮治理不迁移 UI、不实施账号数据库、不部署服务器、不生成 Electron，也不以静态或构建结果宣称用户视觉验收。被外部删除的 CI 工作流未恢复，不能宣称 GitHub Actions 已运行。

构建仍提示部分分块超过 500 kB，主要涉及 Mermaid/图形及应用资源；本轮没有提高告警阈值或开展分包优化。单测有 jsdom 的非致命导航提示，套件无失败。浏览器、生产环境、依赖安全扫描、真实项目完整验收和发布均未执行。
