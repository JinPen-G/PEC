## 实施与兼容约束

- 沿用现有 React、Node、project-core、platform-client 和 platform-contracts 的职责划分，不在治理阶段更换技术栈。
- 对自有代码进行格式统一和必要的职责说明；涉及行为的检查器、质量命令和隔离构建变更单独验证。
- 真实 projects、挂载配置、vendor、品牌原稿和未知输出不参与批量整理；工作区既有与并行产生的删除状态不恢复、不暂存。
- 文档移动前保全原文字节，归档清单注明旧位置与 SHA-256；现行资料按规范、项目资料、界面规范、部署运维归类。
- `quality:core` 使用脱敏样例与独立构建输出；不把正常 build 的真实项目打包副作用隐含进底座检查。
- 新检查器只读维护范围，不执行文档命令、不联网、不读取真实业务项目。其覆盖和限制写入公共指南。

分层整理将浏览器/Node 共用的上下文、语言映射与桥接文本移至 project-shared，原 project-core 文件保留 re-export 兼容入口；不改算法与语言协议。完成证据和原基线问题均见开发记录。
