# 原生页面接入

展示前台使用React原型，后台维护真实项目、菜单与授权；页面业务仅为模拟交互。现行需求查[原生需求](../../docs/原生原型平台/原生原型平台-需求.md)，接入缺口与下一顺序查[后台收口任务](../../docs/原生原型平台/原生原型平台-开发任务.md#15-需求与后台管理复核后的实施顺序)。本文说明实际源码入口，不表示接入流程和后台管理已全部验收。

## 当前目录与来源

- 原型源码在 apps/web/src/project-modules/{moduleKey}/{pageKey}/，页面组件使用PascalCase，项目CSS/模拟数据归该模块。原HTML如被指定为转换输入，只读核对并保留来源/散列，在Preview内实现React，不以iframe或运行时HTML解释器承载业务页。
- 可发布业务Markdown与受控图片在 project-content/{contentKey}/，manifest声明模块绑定、overview、requirements、assets及页面关联；正文在本地维护，网页按统一样式只读展示。
- 内部Preview四册、个人开发记录、协作接续、聊天、来源审计与测试结果留在内部docs/源码位置，不放入业务包。凭证、账号库和配置秘密独立留在服务端。

## 当前注册与加载接点

目前存在三处尚待统一的登记：platform-contracts/native.js是后台模块/页面目录，platform-contracts/showcase.js是展示页源码与构建清单，features/prototypes/native-registry.tsx是原项目工作台注册器。前两个已含RIMO，第三个仅支持empty/orders；不能只添加其中一处就认定前后台可用。NativePlatformApp.openProject还存在RIMO特判，本轮评审已列为待收口，不应为新项目继续复制特判。

页面加载由服务端返回已授权入口，Vite及正式page-assets入口执行相应守卫。后台“添加注册页面”只是配置绑定，不会写入React源码或自动执行上传文件。当前前台只显示负责人指定的RIMO项目；后续项目入口单独安排，不能据此向公共外壳加入真实项目字段。

## 后台与资料关联的已知边界

项目行“配置”中可以维护客户端、菜单和文档关联，但尚无完整的页面路由管理清单。后台project.links与业务manifest页面关联仍由不同消费者使用，不能声称修改后台关联已同步前台PRD。实现前按NP-19/21/24统一有效关联来源；manifest始终承担发布白名单，后台配置不能扩大可发布文件范围。

当前页面级权限与项目文档读取存在评审发现的旁路，编辑者重绑定也存在公开范围校验缺口。扩大公开部署或真实评审人员前先按RV-01/02修复与验证；不能只依靠页面锁定提示、隐藏菜单或前端路由。

## 接入验收

1. 页面/moduleKey/clientId/pageKey和PRD关联可追溯；重复键、无效默认入口、未登记模块与缺失源码有明确失败。
2. 项目模拟状态与平台真实账号/授权写入分离；不调用Rental OS活动运行环境或修改其目录。
3. 管理配置保存后前台排序、上下架、访问地址与文档一致；失败保留草稿，冲突不默默覆盖。
4. 桌面/手机/全屏、主题、三语、键盘、减少动效、滚动目录和弹窗完整验证；源码与PRD分别执行授权检查。
5. 以匿名、仅项目成员、编辑者、获页面授权者与管理员验证详情、文档中心、正文/图片/运行资源直达与撤权；上线与本地证据分开。

工作流程/开源导出和React PRD扩展已被负责人撤回，本模板不恢复那些未经当前范围确认的流程。日常仍为本地开发与文档维护，经GitHub构建发布；真实服务器验收另行执行。
