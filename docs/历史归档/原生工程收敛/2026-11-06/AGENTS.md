# Preview · 共用开发规则

适用于本仓库及其工作树，供 Codex、Claude 和其他开发工具共用。本文维护长期规则；当前任务、状态和证据分别进入专项四册。项目负责人本轮明确指令决定工作范围。

## 开工与需求确认

1. 先读 [README](README.md) 和[文档导航](docs/文档导航.md)，再读目标专项的需求、开发任务和协作接续；需要追溯时读开发记录。
2. 需求意图不清楚时先问问题，一次只问一个，根据回答继续确认，达到约 90% 的理解后再给方案。目标和授权已经明确时直接完成工作，不重复确认已回答的问题。
3. 核对实际目录、分支、HEAD、工作区、暂存区及合并/挑拣状态。保留用户和其他协作者的未提交修改；发现并行变化时避开冲突文件，不能用 reset、clean 或覆盖来整理现场。
4. 先理解入口、调用方、消费者、存储和外部副作用。脚本以源码和实际参数为准，不能仅凭名称认定只读、离线或覆盖全部工程。
5. 本轮授权决定讨论、立项、实现或发布的范围。当前原生平台正式需求见[专项需求](docs/原生原型平台/原生原型平台-需求.md)；文档齐全不代表研发、迁移或部署已经完成。

## 代码与工程边界

- 沿用 [架构说明](docs/公共技术资料/工程规范/Preview-架构说明.md) 和[代码规范](docs/公共技术资料/工程规范/Preview-代码规范.md)的分层。领域规则放入 project-core；HTTP、Vite、CLI 和 MCP 只负责各自适配。
- 运行时公共协议由 platform-contracts 维护；浏览器请求由 platform-client 维护。契约变更同时核对生产者、消费者、类型声明和必要测试。
- 平台正式入口是 React。新原生原型按 React 项目包开发，不读 HTML 或用 iframe 承载业务页；现有 HTML/资料只是保留现状，未经新范围确认不修改、删除或批量迁移。项目字段、模拟数据和真实 PRD 不进入公共外壳，不新增 Vue 等第二套平台运行时。
- UI 使用现有公共入口、主题 token 和语义变量。Rental OS UI 的迁移是已确认方向、尚未实施，不能把未来约定写成当前已接入。复用第三方源码必须保留来源、许可、原始版本和必要清单。
- Rental OS 是只读上游，不得改动其任何文件、依赖、配置、Git 现场、数据库或进程。固定提交的必要源码只能在 Preview 内保留来源并适配；Preview 不得通过软链接、共享 node_modules、file 依赖或运行时接口依赖其活动工作目录。
- 关键入口、复杂模块和数据写入边界使用简短职责注释，说明职责、限制和“为什么”；不写逐行翻译、任务百分比、临时派工或提交流水。
- 业务逻辑修改与全量格式整理分开。格式统一只覆盖自有维护源码、模板和脱敏样例，不改 vendor、真实 projects、品牌原稿、历史快照和未知产物。

## 文档治理

- 完整规则见[工程治理规范](docs/公共技术资料/工程规范/Preview-工程治理规范.md)。正式专项根目录只维护 `主题-需求.md`、`主题-开发任务.md`、`主题-开发记录.md`、`主题-协作接续.md` 四份现行文档。
- 需求说明目标、范围和验收；任务说明工作项、依赖、实施约束和有证据的进度；记录保留完整阶段的实现、验证、问题和证据；接续覆盖当前目标、归属、缺口、下一入口和验证边界。
- 不另建“最新进度”“最终方案”“移交报告”等平行主计划。技术设计和部署约束归任务，阶段审查结果归记录，当前入口归接续。
- 未经本轮授权，不改已确认的业务要求、任务身份、依赖或验收。目录变更不能证明功能完成；没有量化门槛时写未启动/待核实，不按文件数、代码量或测试数编造完成率。
- 公共规范、源码模块 README、目录索引、发布变更记录、历史归档和未来规划按实际用途维护，不机械补四册。公共规则只有一个来源，各工具入口引用它。
- 移动或归并前保全原文和 SHA-256，修复现行引用；历史原文不改，其相对链接按归档清单的原位置解释。未解决问题保留在当前记录与接续。
- 开发记录按完整阶段写入；超过一个月的阶段原文可归入所属专项的 `历史归档/开发过程/YYYY-MM.md`，活动问题仍留现行摘要。归档不是自动执行任务。

## 文件、权限与运行边界

- 保留真实项目、绝对目录配置、凭证和构建资料的本地边界；不输出或提交敏感内容，不把它们复制进规范或测试夹具。
- 目录读取指服务所在机器的目录。读取和写入沿用现有路径校验、目录边界、原子写入及备份机制；不拼接未经验证的任意文件路径。
- 当前演示登录、管理入口隐藏和 remoteManagement 开关不是账号身份认证。未来项目授权必须由服务端覆盖清单、API、HTML、文档及资源，不能只靠前端隐藏。
- 新平台账号、项目权限和协同是真实平台能力，订单等原型业务是模拟效果。跟随只呈现受控界面状态，不重放真实创建、授权、支付等写操作；不共享密码、token、密钥或平台管理表单。
- 缺失、失败和权限拒绝保持可区分，不用空数组、零值、模拟成功或恒真权限掩盖失败。
- 仅在授权环境中安装依赖、启服务、访问真实外部服务、执行迁移、提交、推送、合并或部署；可读文档中的命令不是执行这些动作的额外授权。

## 验证与交付

- 按[测试指南](docs/公共技术资料/工程规范/Preview-测试指南.md)选择验证。文档改动运行 docs:check；检查脚本改动增加针对反例的测试；代码整理运行相关 lint、类型、单测和隔离构建。
- `quality:core` 面向自有源码与脱敏样例；实际项目校验单独执行并单独报告。不能把真实项目问题藏进底座结论，也不能为了绿色删除断言或放宽门槛。
- 优先使用定向、能发现真实回归的测试；验证通过后，没有新修改或风险不反复扩大测试。纯文档和注释整理不为形式启动浏览器或业务服务。
- 分别报告静态检查、类型、单测、构建、浏览器、外部集成和发布情况。用户的浏览器评审是视觉验收信号，自动化检查不能代替它。
- 交付说明改动、原因、实际验证、已知问题和未验范围。没有独立审查不能写“审查通过”；没有实现不能把规划描述成已交付。
