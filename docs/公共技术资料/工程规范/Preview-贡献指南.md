# Preview 贡献指南

维护日期：2026-11-12。仓库维护平台、领域核心、模板与工具；业务资料只按明确发布清单维护，客户资料、凭证及本地运行数据不提交。

## 开始工作

1. 阅读[工程治理规范](Preview-工程治理规范.md)、[文档导航](../../文档导航.md)和本地目标专项的需求、任务、接续。
2. 核对目录、分支、HEAD、工作区、暂存区及合并/挑拣/变基状态，确认成果归属和公共文件唯一写入者。每日首次改动及跨日继续按根规则核对远端同步。
3. 需求不清楚时一次问一个问题；已有明确目标和授权时完成工作。
4. 只读和文档工作使用已有环境，不安装依赖；安装、启服务及外部环境操作先核对本轮范围。新页面按原生项目接入规范开发，不使用已退役的 HTML 项目工具。

## 修改原则

遵循[代码规范](Preview-代码规范.md)与[架构说明](Preview-架构说明.md)。跨项目规则由所属领域包维护，协议变更核对运行时和类型消费者。项目字段、HTML、资源、模拟数据及 PRD 不进入平台公共壳。

注释说明职责和非显然限制，规范说明稳定约束，记录说明完整阶段证据，接续说明当前现场。避免在多个文件重复维护相同计划。

需求和任务正文保持批准依据；任务册日常只更新有据进度。跨树整合使用固定提交或补丁，先保全本次涉及的差异，不复制整个工作目录或追另一作者活动 HEAD。详细执行规则只维护在根 AGENTS。

格式与行为变更分开评估。常规功能只格式化改动文件，不批量改真实项目、vendor、历史或未知输出。

## 验证与交付

按改动选择定向验证；纯文档先运行 npm run docs:check 和改动文件的格式/差异检查。需要底座综合检查时使用 npm run quality:core，范围与副作用见[测试指南](Preview-测试指南.md)。真实项目功能和业务 PRD 单独验收，不混成底座结论。

提交或 PR 必须在授权范围内，只暂存核对的平台源码、配置、测试、公开文档和许可。说明问题、最终行为、兼容影响、实际验证与未验事项；UI 的浏览器交互和用户视觉评审分别陈述。

完成阶段后同步记录、原任务进度与接续，清理自己创建的一次性环境；失败残留按根规则归集或登记原位受阻，不能以测试通过代替收尾。提交、普通推送及远端确认按工程治理规范执行，已有授权不重复询问，不继承其他仓库授权。

需求、任务范围和验收变更要有负责人依据；记录与接续遵守[治理规范](Preview-工程治理规范.md)。没有正式发布证据不编造发布或进度。
