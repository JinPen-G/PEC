# Preview 贡献指南

维护日期：2026-11-05。仓库维护平台、领域核心、模板与工具，真实项目包、客户资料和凭证不提交。

## 开始工作

1. 阅读根 [AGENTS](../../../AGENTS.md)、[文档导航](../../文档导航.md)和目标专项的需求、任务、接续。
2. 核对分支、工作区、暂存区及合并状态，确定写入范围并保留未知 WIP。
3. 需求不清楚时一次问一个问题；已有明确目标和授权时完成工作。
4. 使用已有依赖；安装或启服务前核对本轮范围。新页面按原生项目接入规范开发，不使用已退役的 HTML 项目工具。

## 修改原则

遵循[代码规范](Preview-代码规范.md)与[架构说明](Preview-架构说明.md)。跨项目规则由所属领域包维护，协议变更核对运行时和类型消费者。项目字段、HTML、资源、模拟数据及 PRD 不进入平台公共壳。

注释说明职责和非显然限制，规范说明稳定约束，记录说明完整阶段证据，接续说明当前现场。避免在多个文件重复维护相同计划。

格式与行为变更分开评估。常规功能只格式化改动文件，不批量改真实项目、vendor、历史或未知输出。

## 验证与交付

底座检查使用 npm run quality:core，范围与副作用见[测试指南](Preview-测试指南.md)。真实项目的功能页面和业务 PRD 单独验收，不混成底座结论。

提交或 PR 必须在授权范围内，只暂存核对的文件，不用 git add . 夹带他人成果。说明问题、最终行为、兼容影响、实际验证与未验事项；UI 的浏览器交互和用户视觉评审分别陈述。

需求、任务范围和验收变更要有负责人依据；记录与接续遵守[治理规范](Preview-工程治理规范.md)。没有正式发布证据不编造发布或进度。
