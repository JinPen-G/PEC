# 据点管理

## 用途与双视图

维护实体停车位置及各模式服务能力，层级为车行 → 门市 → 据点。总览每行一个实体据点，能力管理每行“据点＋服务模式”，同一组合唯一。左侧组织树仅用于筛选，不新增或编辑车行、门市。

## 资料归属

实体维护名称、地址、坐标、围栏、进出方式、车位和现场指引。服务能力维护同站、甲租乙还、门市租车、24 小时自助、公务车的能力与启停。柜台服务时间和人工交验车归门市，不重复写入据点。

具备能力与当前启用状态分开：未具备不能选择，已具备但暂停保留配置及历史、不接受该模式新业务。各服务预留车位合计不得超过总车位，保存前检查；实时可租数量还须考虑车辆、订单及整备。

## 预约与还车

普通同站和甲租乙还入口只返回一般预约开放的据点类型及启用能力；租车券按批次指定类型、据点判断。自助还车在同门市启用自助据点范围内，不产生同门市跨据点调度费。

甲租乙还可还车据点须能力启用且可还车空位大于 0，保留旧 APP 空位字段含义及扣减时机。取消能力可能影响实时可还范围，但不自动取消旧订单；基础据点停用与服务关闭分别按确认规则处理，不合并为一项状态。

## 权限与企业据点

总览查看/维护及每个服务模式查看/维护独立配置。只有模式查看权限时直接进入能力视图，不能读取总览或其他模式；车行和门市账号只读取自身范围。导出、新增、编辑和启停分别校验。

营运端默认管理平台据点。企业自建公务据点属于企业并按管理分公司隔离，不混入分时、门市或租车券候选；企业端对平台授权据点只读。

## 历史与验收

修改据点名称、地址或状态不回改订单快照。测试双视图唯一性、车位超额、服务模式筛选、无权字段隔离及甲租乙还旧查询兼容。原 PRD 对历史模型迁移有专项约束，本页不宣称已执行真实数据迁移。
